# Отчёт по лабораторной работе № 3

## Организация командной работы в GitHub

**Проект:** учебное HTTP API для хранения данных.
**Репозиторий:** [cloud-storage-coursework-ersss3530](https://github.com/ersss3530/cloud-storage-coursework-ersss3530).

## Выполненные работы

- Подготовлены API, конфигурация, JSON-файл данных, архитектурное описание и README.
- Созданы Issues в GitHub; они доступны в [списке задач](https://github.com/ersss3530/cloud-storage-coursework-ersss3530/issues). Назначенным владельцем является `ersss3530`, поскольку других участников и логинов пользователь не предоставил.
- Локально подготовлены ветви `feature/docs-architecture` и `feature/readme-documentation`, изменения объединены в локальную `main`.
- Файлы и коммиты опубликованы в GitHub `main`.

## Ограничения командного workflow

Состав команды не был указан. Поэтому приглашение участников и взаимное распределение задач выполнить невозможно. В GitHub не создавались Pull Requests с содержательным peer review и исправлением по отзыву; локальное объединение ветвей не является GitHub PR. Эти этапы остаются незавершёнными и требуют второго участника. Ссылки на ветви и коммиты см. в [истории репозитория](https://github.com/ersss3530/cloud-storage-coursework-ersss3530/commits/main/).

## Вывод

Issues и ветви помогают декомпозировать работу, а PR и review позволяют проверить изменения до слияния. В данном проекте подготовлена основа и опубликованы материалы; полноценный цикл командной проверки требует добавления участника.
