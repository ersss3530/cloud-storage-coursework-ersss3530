# Архитектура учебного облачного хранилища

## Назначение

Прототип принимает HTTP-запросы для чтения и добавления учебных записей и сохраняет их в JSON-файле. Сейчас данные находятся на локальном диске; облачная база данных или поставщик объектного хранения не подключены.

## Компоненты

| Компонент | Ответственность | Интерфейс |
| --- | --- | --- |
| Клиент | Формирует запросы, например с помощью curl | HTTP на 127.0.0.1:8000 |
| API-приложение | Проверяет запросы и обрабатывает список записей | HTTP GET и POST |
| Файловое хранилище | Сохраняет массив записей | JSON-файл по пути из CLOUD_STORAGE_PATH |
| Конфигурация | Задаёт путь к файлу без изменения кода | Переменная окружения |

## Поток запроса

~~~text
Клиент --HTTP--> API-приложение --чтение/запись--> JSON-файл
                         ^
                         |
               CLOUD_STORAGE_PATH
~~~

При GET /items приложение считывает файл и возвращает массив. При POST /items оно проверяет JSON-тело, добавляет запись и сохраняет файл. GET /health возвращает состояние сервера.

## Ограничения

- Сервер слушает только 127.0.0.1 и предназначен для локального учебного запуска.
- JSON-файл не обеспечивает параллельную работу нескольких серверов, резервирование, контроль доступа или облачную отказоустойчивость.
- Для реального размещения потребуются аутентификация, безопасное хранилище секретов, резервное копирование и адаптер к выбранному облачному сервису.
- config/example.env показывает значение настройки; загрузчик .env не включён.
